# Chirpy

A Twitter-like HTTP API server written in Go. Users can sign up, log in, and post short messages ("chirps"). Authentication uses JWT access tokens and database-backed refresh tokens.

Built while working through the [Boot.dev](https://www.boot.dev) backend path.

## Features

- User registration with Argon2id password hashing
- Login with short-lived JWT access tokens (1 hour) and long-lived refresh tokens (60 days)
- Refresh and revoke endpoints for token management
- Authenticated chirp creation (140 character limit)
- Profanity filter that masks banned words with `****`
- PostgreSQL storage with type-safe queries generated by sqlc
- Schema migrations managed with goose
- Request counter metrics and a dev-only reset endpoint

## Tech Stack

- Go (standard library `net/http`)
- PostgreSQL
- [sqlc](https://sqlc.dev) for generating Go code from SQL
- [goose](https://github.com/pressly/goose) for migrations
- [golang-jwt](https://github.com/golang-jwt/jwt) for JWTs
- [argon2id](https://github.com/alexedwards/argon2id) for password hashing
- [godotenv](https://github.com/joho/godotenv) for loading `.env`

## Getting Started

### Prerequisites

- Go 1.22 or newer
- PostgreSQL
- [goose](https://github.com/pressly/goose) and [sqlc](https://sqlc.dev) (only needed if you change the schema or queries)

### 1. Clone the repository

```sh
git clone https://github.com/Keinzou-cl/chirpy.git
cd chirpy
```

### 2. Create the database

```sh
createdb chirpy
```

### 3. Configure environment variables

Create a `.env` file in the project root:

```env
DB_URL="postgres://postgres:postgres@localhost:5432/chirpy?sslmode=disable"
PLATFORM="dev"
JWT_SECRET="<generate with: openssl rand -base64 64>"
```

| Variable     | Description                                                         |
| ------------ | ------------------------------------------------------------------- |
| `DB_URL`     | PostgreSQL connection string                                        |
| `PLATFORM`   | Set to `dev` to enable `POST /admin/reset`. Any other value blocks it. |
| `JWT_SECRET` | Secret used to sign and verify JWTs. Keep it private.               |

`.env` is listed in `.gitignore` and must never be committed.

### 4. Run the migrations

```sh
goose -dir sql/schema postgres "$DB_URL" up
```

Adjust `-dir` to wherever your migration files live.

### 5. Run the server

```sh
go run .
```

The server listens on `http://localhost:8080`.

## API Reference

### Users and auth

| Method | Endpoint       | Auth                           | Description                                       |
| ------ | -------------- | ------------------------------ | ------------------------------------------------- |
| POST   | `/api/users`   | None                           | Create a user                                     |
| POST   | `/api/login`   | None                           | Log in, returns an access token and refresh token |
| POST   | `/api/refresh` | `Bearer <refresh_token>`       | Get a new access token                            |
| POST   | `/api/revoke`  | `Bearer <refresh_token>`       | Revoke a refresh token (204)                      |

### Chirps

| Method | Endpoint                 | Auth                      | Description                                 |
| ------ | ------------------------ | ------------------------- | ------------------------------------------- |
| POST   | `/api/chirps`            | `Bearer <access_token>`   | Create a chirp                              |
| GET    | `/api/chirps`            | None                      | List all chirps, oldest first               |
| GET    | `/api/chirps/{chirpID}`  | None                      | Get one chirp by ID (404 if not found)      |

### Admin and utility

| Method | Endpoint          | Description                                            |
| ------ | ----------------- | ------------------------------------------------------ |
| GET    | `/api/healthz`    | Health check                                           |
| GET    | `/admin/metrics`  | Number of hits to the file server                      |
| POST   | `/admin/reset`    | Delete all users and reset the counter (`dev` only)    |
| GET    | `/app/`           | Static file server                                     |

### Example requests

Create a user:

```sh
curl -X POST localhost:8080/api/users \
  -d '{"email":"lane@example.com","password":"04234"}'
```

Log in:

```sh
curl -X POST localhost:8080/api/login \
  -d '{"email":"lane@example.com","password":"04234"}'
```

```json
{
  "id": "5a47789c-a617-444a-8a80-b50359247804",
  "created_at": "2021-07-01T00:00:00Z",
  "updated_at": "2021-07-01T00:00:00Z",
  "email": "lane@example.com",
  "token": "<jwt>",
  "refresh_token": "<64-character hex string>"
}
```

Post a chirp:

```sh
curl -X POST localhost:8080/api/chirps \
  -H "Authorization: Bearer <access_token>" \
  -d '{"body":"Hello, world!"}'
```

Refresh and revoke:

```sh
curl -X POST localhost:8080/api/refresh -H "Authorization: Bearer <refresh_token>"
curl -X POST localhost:8080/api/revoke  -H "Authorization: Bearer <refresh_token>"
```

### Profanity filter

The words `kerfuffle`, `sharbert`, and `fornax` (any casing) are replaced with `****` in chirp bodies. Words with attached punctuation, like `Sharbert!`, are left unchanged.


## Security Notes

- Passwords are hashed with Argon2id and are never returned by the API.
- Access tokens are signed with HS256 and expire after one hour.
- Refresh tokens are random 256-bit values stored in the database, and can be revoked.
- The reset endpoint is blocked unless `PLATFORM=dev`.
- Use HTTPS in any production deployment, since credentials are sent in request bodies.
